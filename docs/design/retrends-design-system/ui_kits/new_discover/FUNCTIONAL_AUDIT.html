04State and restoration-intent audit

Hard limitation. The mock has no product URL. The one query parameter it reads (?journey=) selects a reviewer scenario at mount and is never written back. Browser history is a stack of in-memory snapshots (pushState with an index into a JS array), so it survives Back within a session and is destroyed by refresh: after reload, Back falls into a hardcoded reset to the Areas city root. Every "should survive refresh" below is therefore an intent statement, described semantically, never as a parameter name.

Misreading risks

  • Not present No quality, ranking, rating or admission-eligibility claim appears anywhere.
  • Not present No travel-time claim; distances are labelled in km only.
  • Risk "Homes within 5 km" is computed as straight-line distance. Without a qualifier, shoppers read radius as commute.
  • Risk Aggregated direction-level counts could be read as "every property here is near all of these schools".
  • Handled The two journeys are kept apart by copy ("keeps this area", "not every home in {area}", "Back to properties in {area}") and by different levels, headings and tints.
  • Risk Selecting a school does change the result set, but the state that results carries no scope indicator, so the change is announced only by prose.

15Product-decision report

  1. Are the school radius and the agricultural distance band committed states? Both change the result set; neither creates history or is presented as a scope. Decide once, for both.
  2. Is a listing detail a state in the journey or an overlay on it? This decides whether Browser Back closes a detail and whether a detail is shareable.
  3. Should a zero-match destination remain visible with a zero count? Affects every navigation level in two journeys, and whether counts on cards can ever read 0.
  4. Do property filters apply to homes near a school? Today they are hidden and ignored while Buy/Rent stays visible. Either scope filters to the journey or apply them and show them.
  5. What does a school count mean at direction and cluster level — located inside, or serving? The per-area meaning is stated; the aggregate is not.
  6. Can Schools and Agricultural searches be saved as alerts? If yes, the alert record must carry journey-specific state, not just areas and property filters.
  7. Where does sign-in sit in the alert flow? Nothing in the mock represents an account.
  8. Selecting one area both navigates and searches. Is that permanent, or is there a browse-without-searching state?
  9. Is Buy/Rent a filter, a separate result model, or a separate journey? It cannot stay an inert control.
  10. How deep is scope-replacement history? Only one previous scope is remembered, so polygon → viewport → return cannot reach the original area set.
  11. May a multi-area selection be non-contiguous? Candidates come from adjacency only; there is no refusal message for a far-apart pair either.
  12. Does the Add-nearby draft survive navigating away, or is it always discarded? Copy says nothing changes until commit, but not what happens if the shopper leaves.
  13. Which journey is the mobile Map mode allowed to be a dead end for? Detail, alerts and confirmations currently exist only in List mode.
