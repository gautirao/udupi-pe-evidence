City Launch — admin workflow

Low-fidelity wireframes + component hierarchy for the internal, admin-only workflow that takes a city from “not started” to “live” on the Udupi Property Explorer. A lightweight launch wizard — not a new application, not a GIS editor.

Reuses existing Discover / DS component New admin-only surface Read-only · safe Starts pipeline (sandbox writes) Guarded / irreversible action ✎ Low-fi — structure & flow, not final visuals
OVERVIEW

The whole workflow, one line

Five stops, minimal clicks. Every step reuses the production Discover experience; nothing here writes to production data. The city only goes live at the very last, deliberately-guarded click.

STEP 1
Select city
Pick a not-yet-live city from the admin list.
STEP 2
Run pipeline
One click prepares geography in a sandbox.
STEP 3
Monitor
Watch stages complete; failures surface clearly.
STEP 4
Launch preview
Validate in the real Discover UX, read-only.
STEP 5
Readiness → Enable
Checklist passes, then enable the city.

Status ladder. A city moves left→right only: Not started → Running → Ready for preview → Ready for launch. The action column always shows the single next step for that row — one obvious click, no menus.
Only entry point that writes. “Run pipeline” is the sole action on this workflow that kicks off work, and it only writes to a sandbox revision — never to live Discover.
Guarded launch. “Enable city” appears only at Ready for launch and opens a confirm dialog (type the city name). It cannot be reached by accident from any other state.
Reuses: admin shell + top nav, Table, Badge (→ LaunchStatusBadge), Button, Select/Input. New: the row model + status ladder only.

Timestamps + current stage. Each stage shows start→end and duration; the running one is amber-striped with a live progress bar above the list. No dashboards, no charts — just the sequence.

SECURITY BOUNDARIES

Where the boundaries are

The whole feature sits behind an admin-only guard. Within it, exactly one page starts work, most pages only read, and no page can touch or accidentally launch production Discover — except the final, doubly-confirmed enable action.

Outer guard. Every route (/admin/cities/*) is wrapped in an AdminGuard. Non-admins never see the nav item, the routes, or the API. The 🔒 lock pill in each screen’s chrome marks this boundary.
Two data worlds. Preview + pipeline operate on a sandbox draft revision, physically separate from the live Discover dataset. “Enable city” is the single, deliberate act that promotes a validated revision to production — nothing else crosses that line.
