# E2E Gate (issue #2750)

## THE gate

```bash
npm run test:e2e:gate        # = bash scripts/run-e2e-gate.sh
```

This is the one authoritative E2E command, locally and (through the same checker script) in CI's
`e2e-canonical` job. It runs the canonical journey suite (`playwright.canonical.config.ts`) against a
real frontend build, a real backend and a disposable local PostGIS fixture, and fails closed.

Sequence, all in `scripts/run-e2e-gate.sh`:

1. Refusals before anything starts (`NOT A GATE RUN: <reason>`, exit 3, variable NAMES only, never
   values): `CANONICAL_SKIP_SHA_PROVENANCE` set, a non-loopback `PLAYWRIGHT_BASE_URL` /
   `BACKEND_BASE_URL`, the shared fixture container name, a missing role credential, a placeholder
   credential, missing tools, an occupied port.
2. Static guards: `scripts/e2e/check-e2e-estate.mjs` and
   `scripts/e2e/check-canonical-journeys.mjs --phase=static`.
3. Collection: `playwright test --list --reporter=json`, then `--phase=list` (4-project roster plus every
   journey id of `e2e/canonical/journey-matrix.json` collected in its own project).
4. Isolated stack: per-worktree fixture container, backend on the gate's own port, rate limiters off
   exactly as in CI. Torn down by a trap on every exit path.
5. Run: `npm run test:e2e:canonical -- --workers=1` (retries 0).
6. `--phase=results`: fails on a missing/unparseable results file, any failed, skipped (including
   setup cascades), flaky or interrupted test, any matrix id not finishing expected+passed in its own
   project, executed != listed, and any role credential value in results/report/traces.
7. Only then: `CANONICAL E2E GATE: PASS @ <sha>` plus counts, and `.e2e-passed` is written (only for a
   clean tracked tree).

Credentials come from the process env, else are read (never written) from `E2E_ENV_FILE` (default: the
worktree's `.env.e2e.local` / `.env.e2e`, else the main checkout's). Ports: `E2E_GATE_FRONTEND_PORT` /
`E2E_GATE_BACKEND_PORT` (defaults 5375 / 8375).

Evidence rule (CLAUDE.md section 11): report command, exit code and counts. A gate that could not run
(for example hosted Supabase Auth unavailable) is `NOT_RUN` with the exact error, never PASS.

## Pre-push hook

`.githooks/pre-push` runs the two STATIC guards (estate guard + journey static check, about a second, no
stack) for any non-doc change and blocks the push if either fails. It prints
`[pre-push] E2E static guards PASSED - this is NOT the E2E gate. Run: npm run test:e2e:gate` and never
claims that E2E passed. Doc-only pushes are `SKIPPED`. `PREPUSH_E2E=gate git push` additionally runs the
real gate and blocks on failure. Classification logic lives in `scripts/dev/lib/pre-push-classify.sh`
and is unit-tested by `scripts/dev/tests/pre-push-classify.test.sh`.

## What counts, and where it is documented

| Question | Answer |
|---|---|
| Which journeys must be proven? | `e2e/canonical/journey-matrix.json` (J01-J16), human view `docs/testing/e2e-journey-matrix.md` |
| What happens to each legacy spec? | `docs/testing/e2e-retirement-manifest.csv` (one row per file, final decision, slice, #2751 title count) |
| How many files / tests exist? | `docs/testing/e2e-inventory.md`, generated by `python3 -I scripts/e2e/gen-e2e-inventory.py` (never hand-typed) |
| May I add a new Playwright spec? | Only by extending `e2e/canonical/` for a documented journey gap, or with an explicit `RETAIN_SPECIALIST` manifest row; the estate guard fails on any unlisted spec |

## Legacy runners (NOT the gate)

`scripts/run-e2e-local.sh` (`npm run test:e2e:local`), `scripts/e2e-watch.sh`, and the `smoke` / `journey` /
`full` / `integration-ui` projects of `playwright.config.ts` are the legacy estate. They print a banner
saying so and are being retired per the manifest (series PR-2 .. PR-7). Do not cite them as E2E evidence.

## E2E applicability rules

| PR type | E2E required? |
|---------|--------------|
| Frontend - new page/route | YES |
| Frontend - existing page change | YES |
| Backend - API consumed by existing FE page | YES |
| Backend - no FE consumer | NO |
| Doc-only / Trivial | NO |

CI note: GitHub Actions billing is blocked for this repo, so CI results are `NOT_RUN` evidence; the
local gate run (HEAD sha, listed/executed counts, unexpected/skipped/flaky = 0) is the authoritative
proof. `scripts/e2e/ci-drift.test.mjs` pins the ci.yml wiring so it cannot drift unnoticed.
